# JupyterLite content tree

This folder is the **source** for the JupyterLite static site that gets
served from [`apps/web/public/jupyterlite/`](../../apps/web/public/jupyterlite/)
when the user clicks **Open Editor** on
[`/imde/notebooks/starter`](../../apps/web/app/imde/notebooks/[id]/page.tsx).

The output is a fully static set of HTML/JS/WASM files — no Python
server is needed at runtime. Pyodide runs the kernel in the browser.

## Files

| Path | Purpose |
| --- | --- |
| `starter.ipynb` | The Colab-like starter notebook, **with executed outputs baked in**. Generated by [`scripts/build-starter-notebook.py`](../../scripts/build-starter-notebook.py). Do not edit by hand — the build script overwrites it. |

## One-time build (regenerate `apps/web/public/jupyterlite/`)

> The static artifact is **committed** to git so the Next.js app can
> serve it without a Python toolchain. Re-run these steps any time you
> change `starter.ipynb` or upgrade JupyterLite.

```powershell
# 1. From repo root, activate the project venv
. .venv\Scripts\Activate.ps1

# 2. Install build deps (idempotent)
pip install `
  "jupyterlite-core==0.6.5" `
  "jupyterlite-pyodide-kernel==0.6.0" `
  "jupyterlab~=4.4" `
  "notebook~=7.4" `
  "nbformat" `
  "nbclient" `
  "pandas" `
  "matplotlib" `
  "scikit-learn"

# 3. Regenerate the starter notebook with fresh outputs
python scripts\build-starter-notebook.py

# 4. Build the JupyterLite static site into apps/web/public/jupyterlite/
#    (the convenience wrapper below also cleans the previous output)
.\scripts\build-jupyterlite.ps1
```

The wrapper script runs the equivalent of:

```powershell
jupyter lite build `
  --contents docs\jupyterlite-content `
  --output-dir apps\web\public\jupyterlite
```

## Pinned versions

These are the versions known to work end-to-end on Windows + Python 3.12:

| Package | Pinned version |
| --- | --- |
| `jupyterlite-core` | `0.6.5` |
| `jupyterlite-pyodide-kernel` | `0.6.0` |
| `jupyterlab` | `~=4.4` |
| `notebook` | `~=7.4` |

If you bump any of these, re-run the smoke test in
[`docs/plans/2026-05-21-001-feat-jupyterlite-starter-notebook-editor-plan.md`](../plans/2026-05-21-001-feat-jupyterlite-starter-notebook-editor-plan.md).

## Why outputs are pre-baked

The in-browser Pyodide kernel takes ~5–15s to download wheels and warm
up. For the executive demo we want the notebook to **render fully
formed** the moment the iframe loads, with the table and charts already
on screen. Users can still click **Restart Kernel** in JupyterLite to
run live.

## What gets shipped under `apps/web/public/jupyterlite/`

`jupyter lite build` emits ~30–60 MB of static assets including:

- `index.html`, `lab/`, `notebooks/`, `tree/` — the JupyterLite UI shells
- `extensions/@jupyterlite/pyodide-kernel-extension/` — the Pyodide kernel wheel
- `files/starter.ipynb` — the notebook served to the iframe via
  `?path=starter.ipynb`

The whole tree is marked `linguist-vendored` in
[`.gitattributes`](../../.gitattributes) so it does not pollute
language statistics. Wheels and WASM files are forced binary.
